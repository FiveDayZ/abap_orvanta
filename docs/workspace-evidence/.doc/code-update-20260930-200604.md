## 2. 本批交付（B）：非相关标量子查询

`WHERE <列> <运算符> (SELECT ...)`，六种比较运算符都收；内层语句由**同一套方言**解析，**必须恰好答出一行**。

- 合法内层形态：无 `GROUP BY` 的单个聚合（`COUNT`/`SUM`/`MIN`/`MAX`），或单个普通列而该读取恰好返回一行。
- 按名拒绝（绝不猜、绝不退化成文本比较）：多行 `TABLE_QUERY_SCALAR_ROWS`（不挑其中一行）、零行同码
  （SQL 的 NULL 与三值逻辑不复刻）、投影不合形态 `_PROJECTION`（`SELECT *`、表达式投影）、内层
  `ORDER BY`/`LIMIT` `_PAGE`、内层语句不被翻译 `_UNSUPPORTED`、嵌套深度 > 3 `_DEPTH`。
- 完整性：内层读取被截断 `TABLE_QUERY_SCALAR_INCOMPLETE`（在**读外表之前**拒绝）；带该比较的外层分支被截断
  `TABLE_QUERY_WHERE_SCALAR_INCOMPLETE`。
- 比较语义与集合测试同一套：类别由两侧字段的 `DD03L` 类型决定，字符类忽略尾随空格、数值类精确十进制；
  `_SCALAR_FLOAT`/`_TYPE`/`_VALUE`/`_TYPE_UNKNOWN`/`_TYPE_UNAVAILABLE`；字符值大小比较按名拒绝
  `TABLE_QUERY_SCALAR_ORDER`（只判定 `=` 与 `<>`）。
- 类型来源：`COUNT` 为本层算出的 `INT4`（`countOperandType`）；`SUM`/`MIN`/`MAX` 取被聚合列的字典类型。
- 发布面：`querySource.whereScalars`（分支序号 / 列 / 运算符 / 内层答出的值 / 内层取值列）；只为比较而读的
  字段在读入后、出答案前删除。

## 3. 根因与修正

1. **共享解析器缺陷（本批发现）**：`WHERE` 尾部原用一条正则切分，`= (SELECT ... ORDER BY ...)` 里的
   ` ORDER BY ` 会被切在括号内部，导致内层 `ORDER BY` 未被认领、`_SCALAR_PAGE` 拒绝来不及触发。改为按括号
   深度扫描的 `splitWhereTail`。两处刻意保持旧行为：不跳过字符串字面量、括号不平衡不返回 `undefined`
   （深度饱和于 0），因此既有测试无需修改。
2. **`readWholeRow` 误判（实现期自查）**：聚合语句的 `readWholeRow` 为 `true`，初版形态判据因此对每个内层语句
   都抛 `_PROJECTION`；改为不依赖该标志，并对 `oneColumn` 显式排除 `columns[0] === "*"`（`SELECT *` 以
   `columns: ["*"]` 承载）。
3. **`exactOptionalPropertyTypes`**：返回 `{where, groupBy: undefined, orderBy: undefined}` 触发 `TS2375`，改为
   条件展开。
4. **A1（同一授权内，已完成）**：前三批四切片首轮真机读数 16/22，六处未过**全部是验收脚手架缺陷**（一条自相
   矛盾的断言、一个本身是精确十进制的取样值、四处外层读取上界低于表真实行数导致按设计拒绝），诊断记录
   `.doc/code-update-20260930-192647.md`、探针 `.cache/r36-probe.json`；修正后 22/22，
   `.doc/code-update-20260930-193631.md`。
