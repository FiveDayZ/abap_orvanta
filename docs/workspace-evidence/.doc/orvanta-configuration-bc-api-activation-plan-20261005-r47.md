4. 实现固定候选的本地路线预检与可审查命令契约：无法证明的动态方法、未知配置键、范围扩展、遗漏恢复项、参数漂移、未开放正确 Customizing 任务一律保持不可执行。复用现有版本/receipt/未知结果保护，不建立通用表写入口。
5. 在路线足够具体后形成真实单次激活申请：确切 API/客户对象、完整受影响键及字段前后值、三语言和共享 PRESS、正确请求/任务、锁/日志/CTS 校验、失败后只读对账与恢复方案。批准作为最终执行步骤；Workbench 请求 472 不替代配置 Customizing 请求。

## 验收条件

| 交付 | 必须证明 |
| --- | --- |
| r46 收口 | 固定构建公开预览正例、原生拒绝、schema 拒绝与五表前后实际读回；无配置写入；真实未覆盖条件继续明示 |
| 路线元数据 | 活动/维护对象/生成源/动态方法具名且可追溯；不以函数名中含 CUNI 推断领域；截断、缺失、变化拒绝 |
| 提交边界 | 每处标准配置写、CTS、日志及 after-import 提交点与错误清理均对应实际源；没有 GUI、隐式对话或未知副作用 |
| 本地契约 | 版本/源/范围/任务/非原子结果和恢复保护的受影响回归、真实 MCP schema 通过 |
| 真实激活 | 仅在另获具体批准后执行；完整值/日志/CTS/锁/无关行与所批内容一致；失联不盲重试、不虚构回滚 |

## 依赖与边界

- 开发、现有范围的 AI 技术测试与只读调查授权继续有效；无需重复批准同一 r46 对象或只读测试。
- 当前登录窗口用于 r46 五表只读预览，不能借此执行激活、修改 KNM/PRESS、配置行录制或号码范围命令。
- 新 RFC 对象级批准及真实配置写范围不得由“继续”扩展。先完成具体源/接口、影响/恢复与执行参数，再确认缺失授权。
- 不释放请求、不重启共享服务、不提交无关暂存内容、不采用 GUI 自动化。
- r46 的真实语法错误与诊断漏报需保留独立故障证据；预检/诊断不能代替真实装载验收。
