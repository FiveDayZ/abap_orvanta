## 实施顺序

1. 刷新已批准对象/函数组的 exact URI 全文、接口、TADIR、E070、非活动清单；保存完整不可变备份。新对象存在性由创建工具验证，不用 URI 搜索阴性推断。
2. 通过专用 create_function_module_with_interface 建立候选接口和正文；读取实际回执、精确源、诊断和各依赖激活状态。已确认不支持的 ATC 不反复探测；不手工维护生成 Include、不改 SAP 标准对象。
3. 所有本地修正完成后冻结一次独立构建和验收脚本。人工口令只进暂存进程环境；实际运行前验证固定构建、正确系统/client/user，不重编译已登录实例。
4. 获取新鲜来源/五表目标/CUNI 元数据版本；读取五表与四表完整前态；两次公开 guard 正例都要包含八键显式 present/missing、全部字段和同一原生保护版本。
5. 原生缺失/畸形版本不得返回保护版本和四表行。公开非法输入在 backend 前拒绝；正常 stale 值在 guard native 前拒绝。核对每次的调用预算、五表/四表/元数据前后同值、源码与接口不漂移；禁止制造真实业务改值或权限改动。
6. 只有存在 named public 成功回执和完整键/范围/版本/前后证据时，才提升新工具 verified；更新索引/开发记录和后续计划。无正例则保持 Partially Verified/unverified。

## 验收条件与证据

固定键：T006I/CLIENT=200 ISOCODE=KPA；T006J/CLIENT=200 LANGU=1,D,E ISOCODE=KPA；T006T/MANDT=200 SPRAS=1,D,E DIMID=PRESS；T006_OIB/MANDT=200 MSEHI=KNM。不存在的行要有命名 missing/null；未返回表、少字段、重复键、其他键、身份/版本漂移必须拒绝，不能伪造缺失成功。数值保持 SAP 字符串，原生零值不能按空值丢弃。

每个公开 guard 最多 2 次 GUARD 原生命令、2 次 host route、10 次 guard 元数据读取；每次原生 GUARD 内 3 次 route 和 2 轮四表固定 SQL。route 的既有 READ/元数据子调用预算继续适用；上述不是总 SAP 往返数，不声称加锁快照。源码审查只允许固定 ROUTE 与 HASH 标准调用。

未覆盖：CUNI 全部行、权限不足真实账号、锁定并发快照、激活、模拟、业务维护/日志/CTS 配置写和恢复。结果不得超出固定八键只读验收。
