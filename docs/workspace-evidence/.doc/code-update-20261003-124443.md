## 五、顺带观测（重要，非缺陷）

DDIC 助手的**读探针**在 `get_capability_report` 中报 `protocol 1.7`，而 `upsert_ddic_structure` / `upsert_ddic_table_type` 在工具索引中声明的最低协议分别是 **1.17 / 1.16**。两次写入**仍然成功**。

结论：该读探针的协议号**不构成写路径的能力门**。`src/capabilities.ts:1235` 的既有文案已经写明这一语义（读探针观测到的协议「不证明能力版本是否安装」）。此项已写入两条登记表 notes 与绊线注释，作为后续判断的参照。

## 八、残留风险与后续优先级

1. **更新路径未验证**：两个工具的「已存在对象 + `expectedVersion`」替换语义仍只有静态推断。若要验证，需对刚建的 `ZORVANTA_R12_*` 做一次受控替换（会改变版本与指纹，需重新读回比对）。
2. **失败路径未验证**：非法对象名、不存在的数据元素、不可传输包、缺传输号等拒绝路径均未取真实观测。
3. **读探针协议号与写能力门的关系**：已观测到「读探针 1.7 但 1.17 写操作成功」这一例，尚不足以断言所有写操作都不受读探针协议约束；建议后续批次继续记录该对照。
4. 余下 **30 条 `unverified`** 受控写工具待逐族验收。
