- 结构替换送入 `description` **50 字符**（`Orvanta R12 acceptance structure (R13 update path)`），写入回显与独立读回均只剩 **前 36 字符**（`Orvanta R12 acceptance structure (R1`）。逐字符核对确认长度恰为 36，非渲染截断。

  `typeName = "TSTCT-TTEXT"`、`kind = "scalar"`、**`maxCharacters = 36`**、`valueContract = { dataType: "CHAR", length: 36 }`。
  ⇒ 截断发生在**助手接口边界**（RFC 形参宽度），既不是服务端守卫也不是 SAP DDIC 上限（`DD02V-DDTEXT` 等为 CHAR 60）。
- **缺口性质**：服务端 `upsert_ddic_structure` / `upsert_ddic_table_type` 等 DDIC 写工具的 `description` 仍声明为无上界的 `z.string()`，调用方无从得知 36 字符上限；超长输入既不报错也不告警，只被静默截断，且回显返回截断后的值。
- **本批处置**：**只记录不修改**（写进两条目 notes 的 `MEASURED LIMIT` 段）。未改 `src/contracts.ts` —— 三个可选修法（仅文档化上限 / 改为拒绝 >36 / 把助手形参加宽到 CHAR 60）中，加宽形参属**载具路线**（必须用户人工 SE38 + F8），改为拒绝属行为变更，均超出本批授权，交用户裁定。
