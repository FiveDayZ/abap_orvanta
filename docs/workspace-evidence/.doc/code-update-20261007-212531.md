## 确认的缺陷根因与修正方法

### 缺陷 1：构建从不携带 JSON 夹具（继承自共享线）

- 现象：`npm test` 中 6 个配置族测试文件以 `ENOENT` 失败，缺 `view-authority-display-w200-r75.json`、`configuration-bte-vim-w200-r76.json`、`bc-route-w200-r71.json`、`configuration-bc-owner-w200-r65.json`、`scpr-activ-protocol-write-w200-r69.json`。
- 根因：`tsconfig.json` 的 `include` 只含 `src/**/*.ts` 与 `test/**/*.ts`，`"build": "tsc"` 因此只编译 `.ts`，**不复制 `test/fixtures/*.json`**；而测试用 `readFileSync(new URL("./fixtures/x.json", import.meta.url))` 相对**编译产物**（`dist/test/`）解析 ⇒ `dist/test/fixtures/` 为空。夹具在源码树里完整存在（6 个，与共享线快照逐字节一致）。
- 佐证：共享线自己的快照 `.cache/spro-checkpoint-20261007/snapshot/dist/test/fixtures/` 里有这 6 个文件 ⇒ 当时是**手工拷贝**进 `dist` 才跑通的，这一步从未写进构建。
- 修正：新增 `scripts/copy-test-fixtures.mjs` 并挂到 `build`。生产包**不受影响**——`test/package-smoke.ps1:49-51` 明确要求生产包不得携带 `dist/test`。

### 缺陷 2：配置 BC 状态目录落在仓库根（继承自共享线）

- 现象：第一次闸门运行后，仓库根出现 `configuration-bc-before-state/bc10a707….json`（6659 字节，内容含 base64 `native-state-test-only`，即测试夹具字节），随后 `format:check` 报红 ⇒ **闸门自我毒化**：第一次跑通不过，第二次跑一定红。
- 根因：`src/tools.ts:1807` 的 `exportRoot = process.env.ABAP_MCP_EXPORT_ROOT ?? process.cwd()`，而 `ConfigurationBcBeforeStateStore` / `ConfigurationBcExecutionStore` 建在 `exportRoot` 之下（`src/configuration-bc-before-state-store.ts:105`、`src/configuration-bc-execution-store.ts:31`）。45 个测试文件构造 `ToolService` 时都不传 `exportRoot`，`ABAP_MCP_EXPORT_ROOT` 也未设 ⇒ 落到工作目录。
- 修正（按仓库对 `adt-discovery_*/` 的既有惯例）：把这两个目录加入 `.gitignore` 与 `.prettierignore`。**这是止血而非根治**：测试隔离缺口仍在，见「Remaining Risks」。
- 已存在的残留文件 `configuration-bc-before-state/bc10a707420e41623ecff207d547751da37e29deef9a1e0d33fca81ce5cdeeff.json` **保留在磁盘未删除**，其清理入口是用户自行决定，AI 不做删除。
