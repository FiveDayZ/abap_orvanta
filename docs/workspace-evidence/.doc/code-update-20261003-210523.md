## 一、确认的缺陷（本批主要产出）

### 1.1 缺陷陈述

`read_abap_screen` 返回的 `fields[]` **无法作为 `upsert_abap_screen` 的 `fields[]` 回送**，工具链在「读 → 改 → 写」这一最基本的闭环上断开。

**实测**：把 `read_abap_screen` 的返回原样作为 `upsert_abap_screen` 的入参（语义空操作意图），被助手拒绝：

```
SCREEN_PROPERTY_INVALID: Unknown screen payload property
```

### 1.2 根因（源码级证实，非推测）

两条路径读**不同**的 SAP 结构，且 `tools.ts` **不做任何转换**（已 grep 确认无 `screenFieldToPayload` / 类似函数）：

| 环节 | SAP 函数模块 | 数据结构 | 词汇表 |
| --- | --- | --- | --- |
| `READ_SCREEN`（读） | **`RPY_DYNPRO_READ_NATIVE`** | `D021S` 原生 | `FNAM` `LINE` `COLN` `LENG` `FLG1-3` `AUTH` `STXT` `RES1/2` … |
| `UPSERT_SCREEN`（写） | **`RPY_DYNPRO_INSERT`** | **`RPY_DYFATC`** 外部 | `NAME` `LINE` `COLUMN` `LENGTH` `TEXT` `PUSH_FCODE` `OUTPUT_FLD` … |
| `PATCH_SCREEN`（写） | `RPY_DYNPRO_READ` + `RPY_DYNPRO_INSERT` | `RPY_DYFATC` 外部 | 同上（**自洽**） |

**实测词汇表交集（读侧 33 键 vs 写侧 57 键）**：**只有 2 个键**（`LINE`、`TYPE`），**且语义不同**——

- 读侧 `LINE` = 已解码的**行号数值**（如 `LINE=3`、`LINE=255`）
- 写侧 `LINE` = 外部结构的行；`validatePublicScreenField` 要求 `LINE/COLUMN/LENGTH` 为**正整数字符串**
- 读侧 `AUTH="101"`（功能码）在写侧是 **`PUSH_FCODE`**
- 读侧 `LENG="12"` 在写侧是 **`LENGTH`**
- 读侧 `COLN="3"` 在写侧是 **`COLUMN`**

**附带发现（佐证词汇表确实不同）**：读侧 `LINE` 存在 `255` 这种「越界」值（SAP 用 255 表示该字段无行号），而写侧 `LINE` 被要求 `>= 1` 的正整数 ⇒ 即使只回送交集键，**也会被本地校验拒绝**。

### 1.3 影响面（分级）

- **`upsert_abap_screen`**：入参契约明写「Accepts public RPY_DYFATC field rows」，**本身无缺陷**——缺陷在**跨工具的读/写不对称**。
- **`patch_abap_screen`**：**内部自洽**（读与写都用 `RPY_DYFATC`），并且工具侧 `screenFieldName()` 同时接受 `NAME ?? FNAM` ⇒ **它可能是可用的**。但它要求调用者提供 `componentOperations[].definition`（`RPY_DYFATC` 词汇表），而**当前没有任何工具能把既有组件读成这个词汇表** ⇒ 调用者只能凭文档手写坐标。
- **`patch_abap_gui_definition`**：本轮未测（CUA 侧，读侧 `read_abap_gui_definition` 返回 `sections`，写侧契约未复核）。

### 1.4 未做修复（裁定边界）

本批授权是「**直接走仓库助手**」——**路线裁定**，不是「修复缺陷」的授权。修复涉及 `src/tools.ts` 的读写转换层（或助手侧改用同一结构），属**产品源码改动**，会触发**重启**要求。**已停止并交回用户裁定。**

## 五、剩余风险与优先级

1. **高（建议优先裁定）**：读/写词汇表不通使屏幕族的「读→改→写」闭环**不可用**。三条工具中至少 `upsert_abap_screen` 与 `patch_abap_screen` 无法在不手写 `RPY_DYFATC` 的情况下完成任务。**修复方向二选一**：
   - **㈠ 工具侧加转换层**（`src/tools.ts` 把 `D021S` 原生字段映射为 `RPY_DYFATC` 外部字段）——**改动局限在仓库侧**，不碰助手。
   - **㈡ 助手侧让 `READ_SCREEN` 增加一路 `RPY_DYNPRO_READ` 输出**（外部词汇表）——需改生成器 + **重新部署助手**（正文路线，无需 F8）。
2. **中**：`upsert_abap_screen` **无指纹守卫**且为整屏替换语义，误用会静默重建整屏。建议在验收时同批评估是否加 `expectedFingerprint`（对齐 `patch_abap_screen`）。
3. **中**：`patch_abap_screen` 的 `componentOperations[].definition` 需要 `RPY_DYFATC` 词汇表，但**无工具可读该词汇表** ⇒ 即便缺陷修好，调用者仍需手写坐标。
4. **低**：目标 `ZCODEX_MCP_DYNPRO` 在 TADIR 中**无任何行**（运行时生成）⇒ 屏幕族写入不产生可归因的传输条目，残留归因需另立口径。
