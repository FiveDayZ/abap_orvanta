## 1. 定案：可用的 headless 接口写入通路

2.24→2.27 的四次尝试全部证伪（详见 `contracts/verification-registry.json` 与 `scripts/bootstrap-sap-helper.ps1` 的能力表注释）。本轮的突破是**不再走 SE37 保存链**：

**`RPY_FUNCTIONMODULE_INSERT`（SAP 自己的创建 API）+ 先退休 TFDIR 行**

| 步骤 | 语句 | 作用 |
| --- | --- | --- |
| 1 | `UPDATE tfdir SET freedate = sy-datum WHERE funcname = …` + `COMMIT WORK AND WAIT` | 按 SAP 自己的方式退休 TFDIR 行（**不删除**）|
| 2 | `CALL FUNCTION 'RPY_FUNCTIONMODULE_INSERT'`（`funcname` / `function_pool` / `remote_call` / `short_text` / `corrnum` + 六张参数表 + `source`）| 一次写齐接口参数表、TFDIR 绑定、TADIR 与实现 include |
| 3 | 若 `sy-subrc <> 0`：`DELETE FROM tfdir` + `COMMIT` + 重试同一 CALL | 仅在退休被拒时才替换残留行 |
| 4 | `COMMIT WORK AND WAIT` | 落库 |

**为什么这条能成**：`RPY_FUNCTIONMODULE_INSERT` **完全不进入 `fu_save_function`**，因此既不 `DELETE REPORT <include> STATE 'A'`、不 `ed_generate_frame` 重建裸框架，也不会触发 `TH_RES_FREE` 会话终止。2.25/2.27 的破坏面（正文清空、TFDIR 行消失）在这条路径上不存在。

**关键约束（本轮实测踩到）**：`RPY_FUNCTIONMODULE_INSERT` 的 `source` 只接受**纯语句体**。它自己根据参数表生成接口头注释；若把预读的完整 include 交给它，include 里会出现**两个 `FUNCTION` 头和两个 `ENDFUNCTION`**（实测：`FUNCTION`/接口注释/`ENDFUNCTION` 各两份，正文指纹 `53313788…` ≠ 基线）。因此必须在插入前从预读 include 中抽出语句体：取**最后一个 `-----` 分隔行之后**、排除 `ENDFUNCTION`、跳过空行。
