## 4. New and Optimized Content

### 4.1 全部ADT客户端对齐原ABAP FS请求标识

- 之前行为：`X-Requested-With: XMLHttpRequest`只用于0.4.0写入专用客户端，普通读取、ABAP Unit、where-used和版本历史客户端没有该请求头。
- 新行为：所有独立ADT客户端统一通过 `standaloneClientOptions()`取得SSL配置和请求标识头；写入客户端复用同一函数。
- 原因：当前可正常工作的原ABAP FS在底层ADT HTTP客户端全局发送该请求头，W200对部分旧ECC端点会根据该请求特征产生不同处理结果。
- 影响范围：独立服务ADT请求；原服务、SAP业务逻辑、MCP工具名称和输入契约不变。

### 4.2 旧ECC类版本历史内容类型重试

- 之前行为：`client.revisions(objectUri)`先以默认 `Accept: */*`读取类元数据，W200返回 `No content handler found for content type '*/*'`，版本历史无法继续。
- 新行为：类元数据默认读取出现该特定错误时，按原ABAP FS已有顺序重试 `application/vnd.sap.adt.oo.classes.v4+xml`至旧版本内容类型；取得结构后再调用标准 `client.revisions(structure)`。
- 原因：错误发生在版本Feed之前的类元数据请求，不是版本Feed解析错误。
- 影响范围：仅 `/oo/classes/`且明确返回内容处理器错误的版本历史请求。其他对象和其他错误继续原样抛出。

### 4.3 能力边界校正

- ABAP Unit从403恢复为正常响应，`ZCL_TESTEE`当前没有测试类。
- where-used从403变为404，说明原“可能无权限”结论不准确；当前W200缺少 `/sap/bc/adt/repository/informationsystem/usageReferences`端点。
- 不新增源码扫描或数据库猜测作为where-used降级，避免向Agent返回不完整结果。

## 5. Fixed Bugs

### 5.1 ABAP Unit被误判为账号权限拒绝

- 错误现象：`run_unit_tests`对已批准对象 `ZCL_TESTEE`返回HTTP 403，尽管ADT discovery公开 `/sap/bc/adt/abapunit`且用户账号可正常编辑。
- 触发条件：独立普通ADT客户端调用W200 ABAP Unit POST，但请求缺少原ABAP FS使用的 `X-Requested-With`标识。
- 根因：独立版只在写入客户端对齐该请求头，诊断客户端没有复用同一配置。
- 影响范围：W200部分旧ECC ADT请求。
- 修复方法：统一所有ADT客户端选项；未改变账号、SAP权限或测试运行参数。
- 回归风险：请求头为原ABAP FS既有行为，不放宽认证或授权边界。
- 验证证据：修复前HTTP 403；修复后返回 `NO TESTS FOUND`、0个测试、未激活对象。

### 5.2 旧ECC类版本历史无法读取

- 错误现象：`get_version_history`返回 `No content handler found for content type '*/*'`。
- 触发条件：对W200类对象 `ZCL_CA_HZ`读取版本历史。
- 根因：`abap-adt-api.revisions()`首先用默认内容类型读取类元数据，ECC 7.31需要显式ADT类媒体类型。
- 影响范围：旧ECC类对象版本历史。
- 修复方法：仅在匹配该错误时重试受控的ADT类内容类型，再复用标准版本历史API。
- 回归风险：没有手工解析版本Feed；后续源码读取仍由标准库执行。
- 验证证据：版本列表返回2个版本；版本1历史源码读取4666行；版本1和版本2比较成功。
