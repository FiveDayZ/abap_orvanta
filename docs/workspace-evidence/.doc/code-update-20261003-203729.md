## 六、剩余风险与优先级

1. **中（R20 的前置）**：屏幕写的**载具路线未定**。源码显示 `UPSERT_SCREEN` 直调 `RPY_DYNPRO_INSERT`，但这与「仓库族接口参数表改动必须走人工 SE38+F8」是两件事，需明确判定，否则可能重蹈「直调内部例程 ⇒ 接口改到了但正文清空」的覆辙。
2. **中**：`ZPMCPC01` 属包 `ZPMC` 的**客户既有对象**；改它的屏幕/CUA 会影响既有功能 ⇒ 属**越界风险**，需用户明确授权或改用运行时生成的无包程序。
3. **中**：`create_new_badi_implementation` 仍是 New BAdI 族**最后一条**未验收工具，需一次性新建授权。
4. **低**：`$TMP` 与包校验在屏幕族**缺失**（首道守卫只查 `iv_request`）——这是**能力缺口**而非缺陷，但意味着工具能写入无 TADIR 归属的程序，**授权边界须由使用者自控**。
5. **低**：`D020S` 不在 `read_abap_table` 白名单，屏幕只能走 `read_abap_screen`（已确认可用）。
