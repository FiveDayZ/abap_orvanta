## 具体实施

1. 原生检查：最终只允许剩余1次正常RCHECK，拒绝4+4已验收不重复；任何失败保存完整响应，不能自行扩充2次正常预算。检查19ordered rows、8/11、原生值前后哈希和既有5个只读API前后观察。
2. 补全副作用前态：从真实SCPRACTR/P/X/XL DDIC和标准读取API获取CUNI十九键旧数据链接、被替换的其他BC Set及可能删除的header/variables/variable-links。使用服务端生成、完整且有界的前态；不接收调用者提供的恢复行。不另建store/operation锁框架。
3. 闭合标准owner：定向定位TRINT_APPEND_TO_COMM_ARRAYS的check_keys/set_cico_comnt及官方精确CTS删除入口，审阅错误、update task、commit、日志/分发与后导入方法的可达性。全局激活链接每调用初始化；不能靠关掉必要标准效果来声称原子性。
4. 完整候选：锁表/键按权威DDIC构造、固定排序、锁内重新核对前态、来源/描述器/任务身份；保护8个共享现存键。官方逐记录维护、链接更新和CTS追加由同一明确顶层提交所有者执行。缺行恢复只按批准的11键执行官方删除；恢复前对账当前版本与本次CTS增量，保留旧条目和其他记录。
5. 外部契约：复用WriteOperationReceiptStore，不新增通用workflow。重复operationId读原回执并只读RECONCILE；历史commit未知时，即使当前值回到before也不得改写为rollback。超时/更新失败保留首错误、真实副作用/锁/CTS结果及人工接管原因。
6. 独立回归/审阅：在新私有构建执行已授权本地测试，覆盖失锁、过期前态、标准保护、语言扩展越界、其他BC Set关联、部分写/CTS失败、恢复中断和重复operationId。完整源码、客户对象/接口、配置前后值/精确键、原生命令/提交/恢复预算全部确定后，才提出需要的具体SAP对象及业务写批准。
