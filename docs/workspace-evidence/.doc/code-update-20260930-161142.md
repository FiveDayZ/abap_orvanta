## 2. 真机证据（w200，全部只读，`maxRows=500`）

### A 组：`ON` 字面量条件可落哪一侧

| 语句 | 预期 | 实测 |
| ---- | ---- | ---- |
| `SELECT A.TRKORR, B.TRKORR FROM E070 A RIGHT JOIN E07T B ON A.TRKORR = B.TRKORR AND A.TRKORR = 'ZZZ_NO_SUCH_REQUEST_OR_TASK' WHERE B.TRKORR = '/SAPMP/CHAR_471'` | 恰好 1 行，A 侧为空，两次读取均完整 | `rows=1`，`A.TRKORR=""`，`B.TRKORR="/SAPMP/CHAR_471"`，`incompleteAliases=[]`，`tables=[A:inner,B:right]` |
| `... RIGHT JOIN ... AND B.TRKORR = 'ZZZ…'`（字面量落在被保留侧） | 按名拒绝 | `TABLE_QUERY_JOIN_ON_ALIAS` |
| `... FULL JOIN ... AND A.TRKORR = 'ZZZ…'`（`FULL` 任一侧的字面量） | 按名拒绝 | `TABLE_QUERY_JOIN_ON_ALIAS` |
| `... FULL JOIN ... WHERE A.TRKORR = 'ZZZ…'` | 按名拒绝且建议已不再是"移入 `ON`" | `TABLE_QUERY_JOIN_WHERE_OUTER_COLUMN`，文案含 "no ON clause can carry it either" = `true` |

第一条是本轮最关键的一条：它同时成立三件事——**字面量只落在这次联接丢得起的那一侧（`A`）**、
**被保留侧（`B`）改用 `WHERE` 收窄**、**结果里 `B` 的未匹配行以 `A.TRKORR=""` 保留下来**。

### B 组：外联接保留语义的计数恒等式

"保留未匹配行"不能靠肉眼看数据断言，改用四种联接的计数必须满足的等式：

```
INNER = M        LEFT = M + A独有        RIGHT = M + B独有        FULL = M + A独有 + B独有
```

在两张**读取都能读完**（`incompleteAliases` 为空，即计数是整个匹配集而非一页）的小表上跑 `COUNT(*)`：

| 联接键 | INNER | LEFT | RIGHT | FULL | A 独有 | B 独有 | 等式成立 |
| ------ | ----- | ---- | ----- | ---- | ------ | ------ | -------- |
| `T001.BUKRS = T001W.WERKS` | 12 | 19 | 45 | 52 | 7 | 33 | 12+7+33 = 52 ✓ |
| `T002.SPRAS = T005.LAND1` | 0 | 41 | 245 | 286 | 41 | 245 | 0+41+245 = 286 ✓ |

第二组最干净：两组键域**完全没有交集**（`INNER=0`），于是 `LEFT` 必须等于左表全部 41 行、`RIGHT` 必须等于
右表全部 245 行、`FULL` 必须恰好 286 行——`LEFT`/`RIGHT`/`FULL` 三种保留语义被同一次测量同时钉死，没有
"看起来合理"的余地。注意这两组 `FULL JOIN` 的两次读取都**没有被任何谓词收窄**（这正是 A 组规则的结果），
所以它们的证据只能来自"两张表都小于行上界"的小表——这一点已写进方言文档。

## 6. 剩余风险

1. B 组恒等式在**三表混合**（如 `A LEFT JOIN B … RIGHT JOIN C …`）上无用例覆盖，属未验证范围。
2. `INNER` 上的字面量条件仍只接受"本次引入的表"（有意收窄，等价写法在 `WHERE`）；对 `RIGHT` 不成立，故按类型分叉。
3. `FULL JOIN` 在两张表都超过行上界时无法给出完整答案（两侧都不允许被谓词收窄），只能返回有界一页并如实标注 `incompleteAliases`——这是规则的正确后果，不是缺陷，但调用方需知道 `FULL` 的证据只能在"两表都读得完"时成立。
