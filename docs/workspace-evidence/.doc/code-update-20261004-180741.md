## 已确认问题及行为变化

1. 专项测试真实复现：写命令响应的 receiptHash 与随后 status 读取的持久化哈希不一致。共享回执存储 finish 的对象字段顺序与 Zod 解码顺序不同，JSON 序列化哈希因此变化。本阶段仅在号码范围包装中读取持久化规范哈希，不改共享回执引擎。回归断言初始响应、对账和 durable status 哈希一致；读取失败保留 unknown，并证明不会派发第二次。
2. 相关回归发现新增工具未进入能力报告；工具虽然可被调用，但报告工具清单缺失。补齐目标范围与 unknown 说明后，协议原有完整覆盖断言通过。
3. 验收登记初稿缺少既有必需字段、method 与 helper 不一致，原校验拒绝；按现有 schema 补齐真实路线与读/写方法，状态仍 unverified。没有修改校验规则或削弱断言。
4. 部署准备发现候选注释最大行宽为 81 / 87，而 create_function_module_with_interface 实际 normalizer 拒绝超过 72 的 RSSOURCE 行。两行注释缩短后两份候选最大行宽均为 72；新清单按当前公开契约验证 4 步，未调用创建工具。旧 r39 不可变证据和清单保留，r40 清单替代其执行用途。
5. 读取返回 snapshot.EV_VERSION，覆盖完整 TNRO 与当前 client 全部 NRIV 行（上限 100）；旧 read_number_range_object 的定义 SHA-1 和只读投影不能当保存版本。保存仅 w200/GR2/200、未使用无缓冲无年度/子对象/分组的客户数值间隔，20 位字符串保持精度，禁止取号、current level 重置、删除或迁移。
6. 同对象所有间隔共用本地保护目标；派发前持久化实际完整版本证据。原生结果、完整回读、提交、标准会话清理及解锁必须一致才判断保存成功。未知结果不重试、不自动回滚；当前状态仅作对比，不证明历史提交或写入归属。
