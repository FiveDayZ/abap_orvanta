## 1. 本批做了什么

`execute_data_query` 降级方言新增第三类「服务端本地判定」条件——**集合测试**：

```
WHERE <列> IN (SELECT <列> FROM <表> [WHERE <合取>])      -- NOT IN 取补集
```

内层语句由同一套文法解析（恰好一列、可选 `WHERE`），读取走同一个读取器与同一读取上界；读取器的结构化筛选
（一个字段名 + 运算符 + 字面量）**没有集合运算符**，因此该测试不能在服务端与读取器之间下推，只能读回后判定。

### 1.1 语义决定（全部写进拒绝文案与文档）

| 决定 | 依据/结果 |
| --- | --- |
| 内层必须恰好一列、无聚合/算术项/`*`/`GROUP BY`/`ORDER BY`/`LIMIT` | `TABLE_QUERY_SUBQUERY_PROJECTION`；**一页不是集合**（`LIMIT` 内层拒绝，且不会被误当成外层的 `LIMIT`） |
| 内层语句本身不被本方言翻译 | `TABLE_QUERY_SUBQUERY_UNSUPPORTED`（不静默改写语句） |
| 嵌套深度 | 上限 3（`TABLE_QUERY_SUBQUERY_DEPTH`） |
| 内层集合读取被行上界截断 | `TABLE_QUERY_SUBQUERY_INCOMPLETE`，且**在读外表之前**拒绝（一行都还没被过滤） |
| 带该测试的外层分支被截断 | `TABLE_QUERY_WHERE_SUBQUERY_INCOMPLETE`（与 `WHERE` 算术项同一纪律：成员资格必须完整） |
| 比较类别 | 由两侧字段各自的 `DD03L` 类型决定：字符类**忽略尾随空格**，数值类**精确十进制** |
| 类别不同 / 类型不在两类之内 | `TABLE_QUERY_SUBQUERY_TYPE`（SAP 会先转公共类型再比；本层不复刻该转换——文案区分两种原因） |
| 浮点字段 | `TABLE_QUERY_SUBQUERY_FLOAT` |
| 值不是精确十进制（含空串数值字段） | `TABLE_QUERY_SUBQUERY_VALUE`（初值在本层没有可放置的值） |
| 类型未取到 / 集合无法读取 | `TABLE_QUERY_SUBQUERY_TYPE_UNAVAILABLE`、`_SUBQUERY_UNAVAILABLE` |
| 被测列 | 读入但**不发布**（输出恰好是语句选中的列）；`WHERE` 未选中该列时也照样读取 |
| 发布面 | `querySource.whereSubqueries`：分支序号、列、是否取反、集合值个数、条件原文 |
| 联接方言 | **不认领**集合测试（落回平台原生错误，不被误读） |
| 相关子查询 | 不在本层方法内（要逐外层行求值）⇒ 写进族 `boundary`，不再是缺口 |
