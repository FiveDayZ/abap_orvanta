### 1.3 根因归因（按排除法，未做隔离实验）

- `RABAX_STATE` 表示助手正文内**未捕获的 ABAP 运行时错误**，即工具在渲染路径上抛异常，违反「回执/渲染路径不得存在可抛异常」的既定契约。
- spool 分支独有的语句只有一处：`CONCATENATE lv_spool_stamp lv_value ls_spool-rqfinal INTO lv_spool_stamp SEPARATED BY ':'.`，其中 `lv_spool_stamp TYPE string`（`scripts/job-spool-source.mjs:11,166`）。
- 同族已验证分支（`JOB_LOG` / `JOB_DETAILS`）使用同一个 `json_field` 宏（`scripts/operational-log-source.mjs:238`）与同样的 `CONCATENATE ... INTO <string>` 形式却正常，唯一差别是 spool 分支多出 `SEPARATED BY`，且其行数据来自 `RSPO_RETURN_ABAP_SPOOLJOB` 的 `STANDARD TABLE OF string`。
- 结论：**`CONCATENATE ... SEPARATED BY` 作用于 `TYPE string` 目标是 ECC 7.31 不支持的形式**，这是 spool 分支唯一的 spool 专属语句。该归因为排除法结论，**未**通过改动后重跑加以隔离证实。

### 1.4 一个被证伪的中间假设（保留以免重走）

第一遍 5 次调用全部返回 `status=not_found` / `code=NOT_FOUND`，一度疑似 arm 的 `authckman = sy-mandt` 谓词永不成立。实测证伪：`TBTCO` **没有 MANDT 字段**，其客户端存放在 `AUTHCKMAN`，w200 上 500 行样本的分布是 `200`=323、`100`=167、`000`=9、`001`=1，故谓词正确；第一遍的候选恰好全部是 `AUTHCKMAN=000` 的作业（`SAP_SLD_DATA_COLLECT` 等），被正确拒绝。
