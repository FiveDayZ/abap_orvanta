## 2. 根因（双重确证，非推断）

上一轮（第四次部署）已把 `USER_LIST` 分支的终止 `CATCH` 改为可归因，真机回报：

```
USER_LIST: READ_ONLY_UNSUPPORTED reason=USER_LIST_EXCEPTION
calleeException=\CLASS=CX_SY_DYN_CALL_PARAM_MISSING
```

`CX_SY_DYN_CALL_PARAM_MISSING` 的含义是「调用函数模块时缺少必填的实参」。本轮据此读取活动接口与标准调用方：

| 证据来源 | 取值 |
| --- | --- |
| `read_function_module_interface`（w200，`TH_USER_LIST`） | 表参数两个：`LIST`（`UINFO`，`optional: false`）、`USRLIST`（`USRINFO`，`optional: true`）；异常只有 `AUTH_MISSSING`；`remoteEnabled: true` |
| `TH_USER_LIST` 正文 | `IF USRLIST IS SUPPLIED.` → 刷新并填充 `USRLIST`；`ELSE.` → 刷新并填充 `LIST` |
| 标准程序 `RSDSUSER`（w200，where-used 命中） | `CALL FUNCTION 'TH_USER_LIST' TABLES list = user_tbl usrlist = user_tbl_v6 EXCEPTIONS OTHERS = 1.`，其后 `DESCRIBE TABLE user_tbl_v6 LINES number_of_users.` |

结论：`LIST` 是**必填**表参数，而 `scripts/runtime-read-source.mjs` 的 `USER_LIST` 分支此前**只传了 `USRLIST`**，动态调用因此缺少必填实参并在内核侧抛类异常。

**同时作废一处旧结论**：`docs/ops-coverage.md` 与 `src/runtime-resources.ts` 原记「`LIST` 含无法验证的 `MSHOSTADR`，**故意不请求**」。该说法不再成立 —— `LIST` 必须传入；但**其输出仍不读取**（同一个无法验证的类型约束），故「只读 `USRLIST`」的对外语义不变。相关静态声明已同批修正。

## 3. 修改内容

### 3.1 SAP 侧助手正文（`scripts/runtime-read-source.mjs` → 生成的 `Z_ORVANTA_OPS_READ` 正文）

改动全部落在 `USER_LIST` 分支，共三处：

1. `runtimeReadDeclarations` 新增声明 `lt_uin TYPE STANDARD TABLE OF uinfo,`（附注释说明「必填、传入但不读」）。
2. 调用处由

   ```abap
   CLEAR lt_usr.
   CALL FUNCTION 'TH_USER_LIST'
     TABLES usrlist = lt_usr
     EXCEPTIONS auth_misssing = 1 OTHERS = 2.
   ```

   改为（与标准程序 `RSDSUSER` 同一调用形态）

   ```abap
   CLEAR: lt_usr, lt_uin.
   CALL FUNCTION 'TH_USER_LIST'
     TABLES
       list = lt_uin
       usrlist = lt_usr
     EXCEPTIONS
       auth_misssing = 1
       OTHERS = 2.
   ```

3. 文件头行结构注释按实测更正（原文写「`USRLIST` … optional in the signature」，未提 `LIST` 必填）。

未使用 7.40+ 语法；生成正文每行 ≤ 72 列（含注释行），由生成器自身的 `assertGeneratedLineWidth` 在构建期强制。
