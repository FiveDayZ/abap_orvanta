## 1. 改动内容（两处，均只作用于失败路径）

### 1.1 `make_time` 的静默中止改为可归因

**改前**（生成器 `scripts/operational-log-source.mjs`）：

```abap
DEFINE make_time.
  lv_date = &1. lv_clock = &2.
  CALL FUNCTION 'DATE_CHECK_PLAUSIBILITY'
    EXPORTING date = lv_date EXCEPTIONS OTHERS = 1.
  IF sy-subrc <> 0 OR lv_date(4) = '0000'
     OR lv_clock(2) > '23' OR lv_clock+2(2) > '59'
     OR lv_clock+4(2) > '59'.
    RETURN.
  ENDIF.
  ...
```

`DEFINE ... END-OF-DEFINITION` 是**文本展开**，宏体里的 `RETURN` 作用于**外层处理块**（整个函数模块），不是宏本身。因此一个不可表示的时间戳会**静默中止整个 RFC**：调用方只看到兜底码 `READ_ONLY_UNSUPPORTED`，与「守卫 `RETURN`」「未批准源」三者**回执完全相同**，无法定位。

**改后**：先写阶段名再中止。

```abap
    job_stage 'JOB_TIMESTAMP'.
    RETURN.
```

**副作用与处理**：ABAP 宏必须先定义后使用，`make_time` 在 `:289` 而 `job_stage` 在 `:334`，而 `make_time` 在 `:310` 就被调用 ⇒ 把 `job_stage` 的 `DEFINE` **上移到 `make_time` 之前**。

**刻意不做的事**：不把非法时间戳降级为 `null`。`scheduledSystemTime` 在服务端 schema 里是 **非空**（`src/operational-logs.ts:110`，`diagnosticTime` 而非 `.nullable()`），且被用于范围比较（`:694-695`）。改成 `null` 会**打穿当前成功的回执**。非法时间戳本就无法诚实表示 ⇒ 正确行为是拒绝并归因，而非伪造一个值。

### 1.2 `SYSTEM_READ` 分支的终止兜底改为可归因

**改前**：

```abap
fail_reply 'ok' 'OK'.
CATCH cx_root.
  RETURN.
ENDTRY.
```

`ev_result` 在 `:342` 已被 `CLEAR`，该 `RETURN.` 前不写任何东西 ⇒ 异常逃逸时回执为空，与守卫 `RETURN`、与未批准源**无法区分**。

**改后**：

```abap
  job_stage 'SYSTEM_READ_EXCEPTION'.
  IF lv_diagnostic IS INITIAL AND lv_body_check IS INITIAL.
    CONCATENATE lv_base
      '"status":"unsupported","code":"READ_ONLY_UNSUPPORTED",'
      '"reason":"SYSTEM_READ_EXCEPTION",' lv_tail INTO ev_result.
  ENDIF.
  RETURN.
```

**为什么必须两者都写**：`job_stage` 只在 `lv_body_check='X'` 或 `lv_diagnostic='X'` 时才写 `ev_result`；**正常模式下它是空操作**，只调它仍会留下空回执。`IF` 分支覆盖正常模式。

**为什么必须走 `job_stage`**：`test/operational-logs.test.ts:537-551` 的用例对闭集做**双向一致**校验 —— 它按正则 `/job_stage\s+'([A-Z0-9_]+)'/g` 扫描 `scripts/operational-log-source.mjs` 与 `scripts/job-spool-source.mjs`，要求 `operationalLogReasons` 里的每个 reason 都能被扫到，反之亦然。手写 CONCATENATE 不会被扫到 ⇒ 首轮 `npm test` 失败于 `the schema accepts a reason no helper stage produces`。改成 `job_stage` 形式后通过。

**刻意不做的事**：不附加异常文本。`CATCH` 内的 `lv_exc->get_text( )` 这类方法调用本身可抛，该处理器不得把「可诊断的失败」变成「空回执」。

### 1.3 服务端闭集同步

`src/operational-logs.ts` 的 `operationalLogReasons` 新增两项：`JOB_TIMESTAMP`、`SYSTEM_READ_EXCEPTION`（各带说明注释）。
