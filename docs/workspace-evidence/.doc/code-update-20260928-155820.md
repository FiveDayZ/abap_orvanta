## 3. 本轮发现（两条，均为“结论与证据脱节”，不是新功能缺陷）

### 3.1 联接**正例**从未有过成功证据（源文案已按证据撤回）

- 全部历史原始产物：`.cache/evidence-ops-n1b/join-positive.txt`、`.cache/evidence-ops-n1c/join-positive.txt`（2026-09-27）与本轮 `.cache/evidence-ops-r23-readonly/join-positive.txt`（2026-09-28）**三份一字不差都是 `socket hang up`**（传输层失败，不是 SQL/方言拒绝）。
- 但 `src/ops-coverage.ts` 的 `query` 族文案写着「The join path was proven on w200 on 2026-09-27 (E070 INNER JOIN E07T returned matched rows…)」，该句被 `npm run ops:matrix:generate` 写进 `docs/ops-acceptance-matrix.md` 第 75/215 行，又被人工文档 `.doc/ops-o0-o9-progress-and-95pct-gap-plan-refresh-20260928.md` 第 155 行引为「OP1-7 联接正例 —— 已闭合」。
- 判据：**「proven」是活体声明，必须由原始产物支撑；本工作区持有的三份产物全部与之相反**。该句已在本轮从源文案中撤回，改写为「实现已在、正例无证据、仅负例已证」，并写明撤回原因与三份产物路径；矩阵随后重新生成即不再声称已证。
- 影响：`.doc/ops-o0-o9-progress-and-95pct-gap-plan-20260927.md` §3.3（第 77 行「联接正例无有效证据（socket hang up）」）与第 152/176 行**原本就是正确的**，本轮不做「回写为已证明」，改为补记第三次同样失败。

### 3.2 三个族的只读工具在补证后仍不可用（与 2026-09-27 结论一致）

`read_work_processes`（TH_WPINFO）、`read_user_sessions`（TH_USER_LIST）两条内核接口返回**空响应**，`read_file_system_directory`（EPS2_GET_DIRECTORY_LISTING）返回 **RFC 失败**；三者**保持 `unverified`、不记 `failed`、不记尝试时间**（凭证/接口层故障不得写成工具失败）。`runtime-resources` 族因此仍不闭环。
