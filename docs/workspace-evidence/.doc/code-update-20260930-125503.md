## 1. 归因修复实测成功（工作② 的关键一步）

上一轮把 8 个 `job_stage` 加进 JOB 分支（每处判据**之后**），并加入服务端闭集 `operationalLogReasons`。重启后实测：

```

→ {"source":"SM37",...,"status":"unsupported","code":"READ_ONLY_UNSUPPORTED",
```

### 4.1 `read_user_sessions` 为何仍拒（定位到行，未修）

生成器 `scripts/runtime-read-source.mjs` **第 126–172 行就是整个 `USER_LIST` 分支**，能产生该码的守卫只有两处：

- **第 134–143 行** 参数守卫：要求 `iv_server`/`iv_dir`/`iv_mask`/`iv_jobname`/`iv_jobcount`/`iv_user`/`iv_program`/`iv_from`/`iv_to`/`iv_status`/`iv_after_job`/`iv_step`/`iv_spoolid`/`iv_page` 全为 INITIAL。服务端本次不送其中任何一个 ⇒ **可排除**。
- **第 164–172 行** 被调方非零 `sy-subrc`：`CALL FUNCTION 'TH_USER_LIST' … EXCEPTIONS auth_misssing = 1 OTHERS = 2`。`auth_misssing` 分支走 `NO_AUTHORITY` 而实测回的是 `READ_ONLY_UNSUPPORTED` ⇒ **排除第 1 支，落在 `OTHERS`（`sy-subrc = 2`）**。

**该分支无法说出原因，本身就是缺陷**：`OTHERS` 分支把 `calleeSubrc` 与 `calleeException` 拼进 `lv_tail`，紧接着调用 `fail_reply`，而 `fail_reply` **整体覆盖 `ev_result`** —— 正文刚构造的诊断细节被丢弃。这与 `make_time` 的裸 `RETURN` 属**同一族缺陷**（诊断信息被丢掉，调用方只看到无归因的兜底码）。

**修复需要改助手正文**（让 `fail_reply` 保留已累积的 tail，或为该分支加一个诊断阶段），**不在本轮已授权范围内，只报告不实施**。
