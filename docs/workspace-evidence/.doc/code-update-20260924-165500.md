## 二、被验收的修复（0.47.10 / 0.47.11 / 0.47.12）

1. **G1（0.47.11 前）**：repository 助手对 `SSF_READ_SAPSCRIPT_STYLE` 的调用有两处类型冲突——表参数用匿名 `TYPE TABLE OF <行>`、键参数用 `TDSSNAME`/`SPRAS`。改为助手自身的表类型 `tsfparas`/`tsfstrings`/`tsftabs`，并以 `tdobname`/`tdobject`/`tdspras` 桥接。载体 `ZORVANTA_MCP_DYNPRO_R11`，`sourceHash` 已核对。

3. **F2（0.47.10）**：匹配路径从 `E070` 回读表头（`TRKORR`）与任务（`STRKORR` + `TRFUNCTION='S'`），使 `status`/`owner`/`target`/`taskNumbers` 不再为空。
4. **`run_abap_program` 前置观察（0.47.12）**：该工具真正的目标是程序自身造成的改动，任何读取都无法界定，故不再尝试快照程序对象，改为记录 `exists=false` 并附说明性 warning（观察状态 `partial`，不阻断调用）。0.47.11 时它因此被安全拦截，`sapInvocationStarted=false`。

## 五、跳过项与原因

- `read_smartstyle` 的 `mode=S` **正例**：`ZTESTSTYLE1` 未读出内容，同样返回 `STYLE_NOT_FOUND`。助手把 `SSF_READ_STYLE` 的全部异常（含 `no_variant`/`no_main_variant`）折叠为同一个 `STYLE_NOT_FOUND`，因此「名称/变式不存在」与「读取成功但空」无法区分，需在助手中回传 `sy-subrc` 才能定位。这是既知限制，未在本次修复。
- `verify:release` / 打包：按用户 2026-09-24 的明确要求不再执行。
