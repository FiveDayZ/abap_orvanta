## 二、语义决定（都写进了拒绝文案、契约描述与文档）

1. **裸限定列不是项**：`A.ZAEHL` 解析成算术项的单列节点，但联接口径与单表口径逐字相同——`node.kind === "column"` 时不认领为项，仍是普通选中列。
2. **项里的列引用照样受联接的限定与别名校验**：`A.ZAEHL * 2` 里的 `A.ZAEHL` 与投影里任何列引用同规（未限定 `TABLE_QUERY_JOIN_COLUMN_UNQUALIFIED`、别名不存在 `TABLE_QUERY_JOIN_ALIAS_UNKNOWN`），不因在项里而放宽。
3. **类型按别名各自表解析，且只解析项真正读到的别名**：`A` 上的项不会因为无关的 `B` 字典读取失败而不可用，也不向 `B` 多问一次字典（端到端用例断言联接项的字典读取只带 `TABNAME = 'T006'`，且无项的联接读字典 0 次）。
4. **求值在联接之后、以联接行为输入，且排在完整性拒绝之后**（与单表路径同序：读不完整先报读不完整）。
5. **发布面与单表路径一致**：操作数列读入但不发布；派生列 `EXPR_1`… 按投影顺序命名并由 `querySource.expressionColumns` 给出映射；派生名不带限定符而选中列全部带，两个命名空间不可能相撞，故这里不需要单表路径的"派生名遮蔽选中列"检查。
6. **外联接未匹配的一侧是空串**：项读到它即按 `TABLE_QUERY_EXPRESSION_NOT_NUMERIC` **指名拒绝**该语句，**不把空串读成 0**（0 是表里从未有过的数字）。
7. **截断的一页允许带项**：每行自己的值是精确的，`truncated` 已说明这不是整个匹配集；这与"`WHERE` 项必须读完"是同一条纪律的两面——**决定成员资格才需要完整，逐行取值不需要**。
8. **联接方言的 `ORDER BY` 每个键都必须限定**，因此不能用 `EXPR_n` 排序：该语句不被认领，落回平台原生错误，不会被静默换成另一种排序。
