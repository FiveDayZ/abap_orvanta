## 2. 根因（本批最终定性）

同一缺陷被发现了两次，原因不是修复无效，而是**修复落错了层**：

- `docs/tool-compatibility-matrix.md:29` 记载 2026-09-20 16:14 已用**人工 SE37** 把 `IV_DESCRIPTION` 的引用类型由 `TSTCT-TTEXT` 改成 `DD04T-DDTEXT`（`AS4TEXT`，CHAR 60），接口指纹 `06b08763…` → `70662f30…`，并记为「缺陷①已修复」。
- 但生成器 `scripts/bootstrap-sap-helper.ps1` 的**共享接口构造器一直声明 `TSTCT-TTEXT`**（L16739，位于 `New-InstallProgram` 内、按 `$FunctionName` 分叉的 `$operationDbField` 判断之外）。
- ⇒ **该人工修复被其后任一次助手部署静默覆盖回退**，线上退回 CHAR 36。R13 于 2026-10-03 重新发现同一缺陷，即此漂移的产物。
- **真正的归属点是生成器**。R14c 因此改生成器，而不是再改一次 SE37。

### 3.3 刻意保留「只声明不强制」

`description` 输入仍是**无上界的字符串**。超 60 字符仍会被 RFC 层截断且写入报成功。拒绝超长属**收窄已接受取值**，需显式裁定；用户本次裁定的是选项 C（加宽），未裁定选项 b（`.max(60)` 拒绝）。
