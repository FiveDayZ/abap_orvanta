## 最小交付与顺序

1. 保持修正版构建冻结：登录就绪后执行同一公开只读验收，捕获原生字段格式，两次 CUNI/T 路由及版本、schema/原生拒绝、完整五表前后相等。先确认根因及真实成员/方法，失败保留回执并对账，不盲重试。
2. 依据真实 OBJM 方法名完整读取源、接口、函数组全局状态和副作用依赖；逐项核对所有 OBJS 成员的 DDIC 键、权限、数据与恢复范围。审查实际方法提交、更新任务、日志、跨 client 和 GUI 依赖；未知保持不可执行。
3. 完成固定 EHS_CUNI_KNM/N 的本地激活准备契约：绑定 source/target/candidate/metadata/method-source 版本，明确 language 与 USE/FIX/VAR 策略、指定 Customizing 任务和所有者、完整 before/after 键、共享 PRESS 保护、锁内版本校验和只读 reconcile。复用现有 receipt 设施；不接收任意表、任意方法、自由提交/绕过系统检查开关。
4. 将客户 RFC 源候选、精确接口、配置影响与恢复清单做成具体部署/执行申请。Workbench 472 仅覆盖已批准客户对象开发，不替代配置请求。只有必要对象与真实配置写入得到相应批准后才执行；不得把本阶段批准继续解释为激活整包或释放请求。

## 验收条件

- 只读路由真实通过；成员、方法、调用链源指纹稳定且完整，跨范围或漂移明确拒绝。
- 标准提交点和异常行为有真实源证据；日志/CTS/配置可能分别生效时采用部分或未知回执，禁止虚假整体原子性。
- 本地公开 MCP schema、权限/范围、过期、未知结果、重复操作和恢复拒绝测试通过；测试授权持续有效。
- 经另行具体批准的真实激活须逐键、日志、CTS、锁及共享行对账；超时先只读 reconcile，不能重复执行未知写。
