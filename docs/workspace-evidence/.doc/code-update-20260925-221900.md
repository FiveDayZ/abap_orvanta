## 3. 本次确认的两个事实性缺陷（均为可发现性问题，非运行错误）

### 3.1 降级方言要求 `maxRows ≤ 500`，超出时暴露原生平台错误

`src/tools.ts`：`rowCap = min(maxRows ?? 1000, 1000)`，随后 `if (!structured || rowCap > 500) throw error`——即 `maxRows` 缺省为 1000 时，语句在解析成功后被**直接抛出原生错误** `SAP_DATA_QUERY_RESPONSE_INVALID`，调用方看不到"上限是 500"这条规则。实测：不带 `maxRows` 的 `SELECT *` 得到原生错误；带 `maxRows=50` 同一语句立即走 `rfc_read_table` 方言返回数据。工具描述里没有这条上限。处置建议（未在本次修改）：把上限写进描述，或把越界的 `rowCap` 直接夹到 500 而不是抛错。

### 3.2 `read_ddic_structure` 只接受结构体

对表调用返回 `SAP DDIC helper rejected the operation: OBJECT_TYPE_MISMATCH: Dictionary object is not a structure`。表的字段清单应改用 `read_abap_table`（或 `execute_data_query` 返回的 `fieldMetadata`——本次正是用它拿到 `ZTPMC_BZWL` 的 6 个字段）。此为调用语义，不是缺陷；记录以免再次误用。
