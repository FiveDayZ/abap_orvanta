在独立仓库根目录执行：

```powershell
npm.cmd run test:w200-debug-acceptance
```

默认连接已启动的 `http://127.0.0.1:4847/mcp`、系统 `w200`。使用配置中心已经保存在内存中的登录，不再次索取密码，不读取其他进程环境，不启动第二个 SAP 服务。
地址可通过 `ABAP_MCP_ENDPOINT` 指定其他本机端口，连接通过 `ABAP_MCP_CONNECTION` 指定。
脚本仅接受无凭据、无查询参数的本机 HTTP `/mcp` 地址。

从 0.36.28 开始，默认模式执行测试函数接口/源码指纹、仓库分配、调试状态与只读能力预检。不会启动或停止监听、设置断点或调用 RFC，不修改源码、包、传输和业务数据。存在其他调试会话时退出，不接管它。

脚本先核对在线版本与构建版本一致，并确认新 precheck 动作已注册；旧服务会在任何 SAP 调用之前被拒绝。每次执行在工作区根 `.doc/m64-debug-acceptance-<时间>.json` 保存证据。

退出码：0 为完整用例通过，2 为部分验证/环境或授权阻塞，1 为用例失败或清理失败。HTTP 404 不会被报告为调试通过。

## M6.5 只读能力预检（0.36.28）

```json
{
  "connectionId": "w200",
  "action": "precheck"
}
```

通过 `abap_debug_session` 调用。保持原 start/stop/status 动作及默认 start 不变，不增加工具数量。

- 先 GET ADT Discovery，检查 debugger、listeners、breakpoints 三个精确资源是否被通告。
- 未全部通告时返回 `not_advertised`，不继续请求监听器；这不证明 SAP 没有调试能力。
- 全部通告后只 GET 监听冲突，不发送创建、停止或接管监听的请求。
- 返回 `metadata_available` 仅代表元数据与冲突查询返回，不证明后续断点、暂停、变量、单步、停止协议受支持。
- GET 监听返回 404 时为 `not_found_ambiguous`，不会将“没有监听”推断成“端点不存在”，也不会跳过检查并自动 POST。
- 401/403、其他 HTTP 错误、无 HTTP 状态的网络错误分别保留；不输出原始响应、令牌或后端错误正文。
- 始终返回 `readOnly=true`、`listenerStarted=false`、`executionValidated=false`。

2026-09-10 的 W200 活动源码核查发现：

1. `CL_TPDA_ADT_RES_APP` 在 `CL_TPDAPI_SERVICE=>IS_DEBUGGING_AVAILABLE` 为初始值时不注册调试路由。
2. 可用性取决于 attach 内核支持及 `TPDAPI_NO_KERNEL` 用户参数；源码不等同于这些条件的实时返回值，本轮未修改参数或内核。
3. 旧 `CL_TPDA_ADT_RES_LISTENERS` GET 在无活动监听时抛 not-found；停止行为在 POST 的 deactivated 分支中，而现有 SDK 用 DELETE。

因此不能仅凭历史 404 宣布系统永久不支持，也不能只忽略 404 就启动旧版协议。旧版监听、暂停、停止和会话归属兼容性仍需独立验收；0.36.28没有启用旧版适配或绕过标准限制。

## 获批后执行

固定对象为 `ZCMCP_FM_1501`，函数组 `ZCMCP_FG_1501`。
脚本冻结了 2026-09-07 回读的完整接口/源码指纹；发现变化时拒绝执行，不能为让测试通过而自动更新基线。
执行前应确认函数组初始化和共享数据依赖，并取得准确函数和输入的运行授权。保持其他开发者不修改该测试对象；客户端指纹检查不是跨整个调试过程的 SAP 原子锁。

只有获批后才设置以下标志：

```powershell
$env:ABAP_MCP_DEBUG_ACCEPTED = "ZCMCP_FM_1501"
try {
    npm.cmd run test:w200-debug-acceptance
} finally {
    Remove-Item Env:ABAP_MCP_DEBUG_ACCEPTED -ErrorAction SilentlyContinue
}
```

完整技术用例包含：

1. 设置 `IF iv_input IS INITIAL` 源码断点并确认已验证。
2. 通过 MCP 的 `test_remote_function_module` 发起输入 `VALIDATION` 的真实 RFC。
3. 等待 SAP 真正暂停，读取非空调用栈，确认 `IV_INPUT=VALIDATION`。
4. 单步后确认执行位置变化，继续并核对 `EV_OUTPUT=MCP:VALIDATION`。
5. 删除测试断点，测试 20 字符边界 `12345678901234567890` 和空输入声明异常 `INVALID_INPUT`。
6. 核对监听退出、断点数为零、源码指纹和仓库分配不变；清理失败使整个结果失败。

脚本不删除测试对象，不清除 SAP 业务锁，不创建或释放传输，不自动重试 RFC。
120 秒是 MCP 客户端调用等待上限，不是 SAP 事务取消保证；调用超时后仍须在 SAP 核对结果。
旧 `test:w200-debug-wave` 是历史独立启动/SOAP 验证入口，本轮未运行；使用配置中心时优先使用上述新入口。

## 典型业务验收

文本拼接测试函数只能证明技术链路。真正业务验收必须先指定业务对象、RFC/报表、组织范围、测试主数据与单据、允许变更及清理方式，再读取活动源码、接口和关联依赖。

| 场景                   | 验收要求                                                   |
| ---------------------- | ---------------------------------------------------------- |
| 正常提交               | 响应业务状态正确，持久化主/子表、数量单位、审计字段一致    |
| 必填/域值/主数据错误   | 明确错误，无部分数据写入                                   |
| 权限与组织边界         | 使用获批测试用户验证，不能靠单一管理员账户推断             |
| 重复提交与重复状态流转 | 原始业务键与结果可核对，无额外单据或错误状态推进           |
| 并发/陈旧更新          | 使用独立会话验证锁和状态前置条件                           |
| 失败与回滚             | 经批准的故障点证明无部分持久化；禁止临时破坏生产流程       |
| 清理                   | 核对单据、预留、锁及审计结果；沿用业务撤销流程而非直接删表 |

当前已确认入库计划业务流程并获准开始只读核对；准确业务输入及持久化测试范围尚未冻结，因此以上业务矩阵尚未执行。真实 WorkBuddy 工具调用也需单独留证，SDK 调用不能替代客户端验收。
