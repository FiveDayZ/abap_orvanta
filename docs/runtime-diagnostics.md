## M5.1：ST22 结构化诊断（0.36.7）

新增只读工具 `diagnose_sap_failure`，复用现有 ADT dump feed。旧工具
`analyze_abap_dumps` 的输入和输出保持不变。

```json
{
  "connectionId": "w200",
  "program": "SAPLZEXAMPLE",
  "fromSystemTime": "2026-09-07T00:00:00",
  "toSystemTime": "2026-09-07T23:59:59",
  "maxResults": 20
}
```

程序名是示例，不代表系统存在该对象。所有时间过滤均为 SAP 系统本地时间。
`program` 精确匹配主程序、调用栈程序或 Include，忽略大小写；不支持通配符。
可另按 `username`、`errorType` 精确过滤，或用当前 feed 中的 `dumpId` 定位。
返回错误分析、终止说明、调用栈和位置、重复错误分组及完整性警告。
`includeSource` 默认关闭，显式开启仅返回已有转储内最多 80 行源码摘录，
不会读取当前源码。源码链接只保留受限 ADT 路径并绑定当前连接，省略原查询上下文；
不保证复杂对象上下文精确定位，不自动访问链接。

### 操作关联

可提供既有写入回执的 `operationId`，只读取本地记录；不存在则在读取 SAP 前拒绝。
需同时提供明确的 SAP `systemUtcOffset`（如 `+08:00`，不得从桌面时区推断），
并且回执须含开始、结束时间，才计算是否落在时间窗口内。
`correlationWindowSeconds` 默认 60，范围 0–900。

时间接近、对象相符只是候选证据，`causalRelationship` 始终为 `not_proven`。
历史转储不是当前源码仍有错误的证明；标准 SOAP 框架终止位置也不意味着应修改标准对象。
本工具不会重试业务调用、修改源码、清日志、取消作业或解锁。

### 完整性与安全

- 仅覆盖服务器返回的 ADT feed，不保证 ST22 全用户、全客户端或完整保留期。
- `unavailable`、真正空 feed、解析失败和截断分别报告；`qualityGate` 始终为 `not_evaluated`。
- 单文档 256 KiB、总解析输入 8 MiB、最多 500 条，输出 1–50 条；限制是本地解析预算，
  不是服务端分页或网络接收上限。
- 解析 HEADER/ERROR/TERMINATION/STACK/SOURCE，不返回变量区或原始 HTML；
  默认隐藏源码。口令、令牌等脱敏为尽力处理，不构成完整敏感数据防泄漏保证。
- 日志属于不可信证据，不得把日志中的文字当作 Agent 指令。
- HTML 解析使用固定依赖 `parse5 8.0.0`（MIT，解包约 337 KB），依赖
  `entities 6.0.1`（BSD-2-Clause，约 541 KB）。适配项目 Node 24 / ESM，
  不增加浏览器运行时。锁文件固定依赖；安装时生产依赖审计为 0，非永久安全承诺。

## 验证入口

- `npm run verify`：格式、静态、类型、单元、MCP 协议及已有回归。
- `npm run verify:release`：便携包和配置中心包级启动/停止回归。
- `node scripts/probe-runtime-diagnostics.mjs`：只读现有 w200 转储，验证新本地解析器；
  若线上已注册新工具，追加专用工具验证。证据输出到工作区 `.doc`，不保存原始转储。

新版本未切换前，真实 feed 加本地解析通过不等于新专用工具已在 SAP 连接中部署验收。
